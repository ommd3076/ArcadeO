## Results

- **A10-T1 — shell precache and selected-game loading:** `build-public.mjs` reads the Vite manifest’s actual `index.html` entry and walks only its static import graph for shell precache. The public runtime asset inventory is sorted and included in the cache revision digest, so changing a lazy-only asset rotates the cache and activation removes the prior `arcade-shell-*` cache without precaching lazy route/board chunks. The final candidate build used revision `f52349b96247d7ee`: 48 public inventory paths, 11 precache entries, 600,772 precache bytes. The service worker caches runtime public assets on demand. MatchScreen selects one lazy board at a time and exposes a visible loading state. The performance trace shows only the Connect Four board loaded before the route-cycle portion of the test.
- **A10-T2 — bounded offline recovery and privacy:** the fetch handler bypasses external origins, non-GET requests, any query string, exact `/api`, and `/api/*`. It does not cache account/session/API data or choices and it does not call `skipWaiting` or reload active match clients. Offline navigation falls back to a fresh `Response` made from the cached shell body and headers; it does not reuse the redirected `/index.html` response metadata. Final PWA testing observed cold `/games` recovery, disabled retry while offline, online `/api/health` and `/` responses at 200, and a real `/games` chunk response at 200 after retry. The route reached all eight games. The auth retry reload fix was integrated by the lead; this test does not claim offline game actions or private-state persistence.
- **A10-T3 — comparable performance and board chunk evidence:** final evidence is `planning/review/evidence/owner-corrections/performance-overnight-final.json`; the earlier `performance-overnight-after.json` is retained as an intermediate measurement before the final font/index preload change. Conditions were Chromium 153.0.8010.12, 1280×900, three cold/warm repeats, cold CPU rate 4 with 50 ms latency and 1 MiB/s, service worker blocked for comparable loading runs, unthrottled Worker input, and headless rAF capture. Initial static app JavaScript gzip is 148,693 bytes, below the 250 KiB budget. The final cold total decoded JavaScript is 451,168 bytes versus baseline 445,074 (+6,094); this is not a global JavaScript-size reduction. The selected Connect Four session loads its board chunk on demand. Cold FCP means were 594.7 ms final versus 933.3 ms baseline; warm FCP means were 288.0 ms versus 298.7 ms, while the first warm sample regressed from 284 ms to 292 ms. Cold transfer was 183,788 bytes versus 210,216, and decoded font bytes were 27,348 versus 55,852. Pointer-to-accepted-disc DOM latency samples were 15.3–17.0 ms final; the comparable baseline samples were around 20.4 ms. Captured rAF maxima remained about 16.7–16.8 ms. These are local measurements, not causal claims or device performance guarantees.
- **A10-T4 — hidden polling and cleanup:** the leased match-session timer callback now returns without polling when the document is hidden, and an in-flight poll does not schedule the next timer after the document becomes hidden. Visibility restoration resumes the bounded poll; disconnect cleanup remains in place. The regression forces a pending timer callback while hidden and verifies no fetch/timer, then verifies visible polling and teardown. It does not change transport, accepted IDs, guards, or retry behavior.
- **A10-T5 — repeated route/resource trace:** after six route cycles, active WebSocket count remained 1 and listener count was unchanged. The final sample reported 7 sockets created across the run and one active at the end. Connected nodes increased by 7 and collected precise heap increased by about 1.27 MB (baseline route-cycle heap increase was about 1.10 MB); this is not an improvement claim and does not by itself establish a leak. Metrics and loaded asset paths are in the final performance JSON.

## Investigation notes and limits

The first offline navigation attempt failed because the cached shell response retained redirect metadata; reconstructing the response fixed that cold navigation. An early online retry test then stopped at RouteRecovery after AuthState retry because the router retained its failed lazy import; the lead’s auth error retry now reloads the current document and disables retry while offline. The startup retry test initially re-injected its artificial stalled auth response after that reload; its test-only marker now persists in `sessionStorage`, and the full startup/PWA/auth-race rerun passes. The terminal performance JSON includes the later approved font preload and is the comparison artifact; do not use the intermediate JSON as final.

Build, unit/SSR, and desktop Chromium evidence do not qualify physical phones, production deployment, or two-account device recovery. Final integrated source may receive lead/A11 changes after this report; those require the lead’s final fresh build and full acceptance run. All A10 source, test, and browser-slot leases are released; no shared ledger or acceptance status was changed here.
