## 2. Findings and Contract Compliance Audit

### A. Server Authority & SQLite Transaction Integrity
- **DO Transaction Atomicity**: In `worker/matches/match-do.ts`, moves execute within synchronous SQLite transactions (`transactionSync`) followed by `storage.sync()`. State modifications, event appends, action receipt writes, and projection outbox enqueueing happen atomically.
- **Outcome Authority**: The client UI (`MatchScreen` and `ConnectFourBoard`) renders based exclusively on `view.gameState.board` received from server snapshots and events. No client-side speculative win detection or optimistic completion is present.

### B. Action Idempotency & Concurrency Guards
- **Action Envelope**: Actions supply unique UUID `actionId`, `expectedVersion`, `turnId`.
- **Receipt Checking**:
  - Replaying identical `actionId` with matching digest produces cached `AcceptedReply` with identical version and event ID.
  - Submitting identical `actionId` with differing payload correctly fails with `ID_REUSED`.
  - Replay after newer moves have settled fails with `ACTION_SUPERSEDED`.
- **Concurrency & Turn Authority**: Moves out of turn are rejected with `NOT_YOUR_TURN`. Moves on an occupied/full column are rejected with `INVALID_ACTION`.

### C. Offline, Takeover, & Reconnect Recovery
- **Offline Input Pause**: When disconnected (`connectionState !== 'connected'`), inputs are disabled and the `ConnectionStatus` banner announces "Disconnected — inputs paused".
- **Takeover Endpoint**: `POST /api/v1/matches/:id/controller` increments controller generation and invalidates earlier controllers.
- **Reconnect Catch-up**: `MatchSession.reconcile()` fetches latest snapshot, detects version gaps, drops stale in-flight commands, and restores consistent state.

### D. Auth, Privacy, & Session Security
- **Web Crypto Qualification**: PBKDF2 with SHA-256 at 600,000 iterations passes RFC 6070 test vectors.
- **CSRF Defense**: HMAC-SHA-256 CSRF tokens derived using server secret and session token; verified on all mutating state requests.
- **Rate Limiting**: `login_limits` table successfully throttles repeated login failures (5 failures per 15-minute window).
- **Zero Public Secret Leak**: Connect Four public views expose only public grid tokens.
