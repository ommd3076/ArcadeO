# Task Report: F02 - Auth and Database Foundation

- **Task**: F02

## Owned Paths and Files Changed
- `migrations/0001_initial_schema.sql`: Full D1 initial schema covering `accounts`, `sessions`, `login_limits`, `puzzles`, `match_registry`, `active_slots`, `results`, and `sudoku_records` with exact foreign keys and indexes.
- `migrations/seed_accounts.sql`: Generated initial seed SQL for Player A and Player B.
- `worker/auth/types.ts`: TypeScript contracts for accounts, sessions, rate limits, safe profiles, and auth API responses.
- `worker/auth/crypto.ts`: Standard Web Crypto utilities for constant-time comparison (`timingSafeEqual`), SHA-256 hashing, HMAC-SHA-256 signing, and cryptographically secure random bytes.
- `worker/auth/kdf.ts`: PBKDF2-SHA256 password hashing and constant-time verification using OWASP-recommended 600,000 iterations and 16-byte random salt; benchmark helper.
- `worker/auth/session.ts`: 256-bit cryptographically secure session token generation, D1 session persistence, HMAC-SHA-256 session-bound CSRF token derivation, session validation against D1 primary, revocation, and `arcade-session` / `__Host-arcade-session` cookie handling.
- `worker/auth/rate-limit.ts`: Bounded rate limiting stored in `login_limits` (5 failed attempts per account per 15 minutes, 20 per IP address), window expiration pruning, and reset on successful authentication.
- `worker/auth/index.ts`: Re-export barrel for auth module.
- `worker/api/auth.ts`: Auth endpoints router (`handleAuthRequest`):
  - `POST /api/v1/auth/login`: Rate limit check, constant-time dummy verification on missing user to prevent timing attacks, password verification, cookie issuance, and safe profile return.
  - `GET /api/v1/auth/session`: Session validation against primary D1, CSRF derivation, and profile return (or unauthenticated status).
  - `POST /api/v1/auth/logout`: Origin check, session-bound CSRF token verification, atomic revocation in D1, and cookie clearance.
- `scripts/provision-accounts.mjs`: Account provisioning utility that reads environment variables (or safe defaults) to hash credentials and generate seed SQL for Accounts A (player_a, standard, teal) and B (player_b, romantic, violet) without echoing secrets.
- `scripts/provision-accounts.d.ts` & `scripts/provision-accounts.d.mts`: TypeScript typings for provisioning module.
- `tests/integration/auth/d1-mock.ts`: In-memory `D1Database` mock adapter powered by Node.js 24 built-in `node:sqlite` `DatabaseSync` for zero-mock, real-SQL testing.
- `tests/integration/auth/auth.test.ts`: Integration test suite covering KDF qualification with RFC test vectors, 600k-iteration benchmarking, migration execution, account provisioning, login, rate limiting, session bootstrap, CSRF protection, and logout revocation.
