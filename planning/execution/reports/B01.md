## Owned Paths and Files Changed
- `worker/matches/types.ts`: DO SQL row interfaces (`MatchSnapshotRow`, `EventRow`, `ActionReceiptRow`, `PrivateRoundChoiceRow`, `ProjectionOutboxRow`), in-memory `SnapshotData`, initialization params, and projection payload types.
- `worker/matches/digest.ts`: Canonical SHA-256 payload digest calculation with recursive key sorting to guarantee deterministic serialization for action idempotency and reuse checks.
- `worker/matches/match-do.ts`: Cloudflare Durable Object implementing the SQLite-backed Match Authority:
  - Tables: `match_snapshot`, `events`, `action_receipts`, `private_round_choices`, `projection_outbox`.
  - 7-step Acceptance Pipeline:
    1. Authenticate actor session and verify controller generation.
    2. Check existing action receipt: returns cached reply on identical digest, rejects with `ID_REUSED` on different digest, rejects with `ACTION_SUPERSEDED` on superseded tombstone.
    3. Guard checks: expectedVersion, turnId, roundId, lifecycle, and turn seat.
    4. Pure reduction via `getGameEngine(gameId)` from registry.
    5. Atomic synchronous SQLite commit via `transactionSync` (updating snapshot, appending event, writing receipt, enqueueing projection outbox).
    6. Durable storage synchronization (`await storage.sync()`).
    7. Filtered response generation, WebSocket broadcast to connected clients, and async projection outbox flush to D1 `match_registry` and `results`.
  - Controller takeover (`handleControllerTakeover`): increments generation atomically and invalidates stale controllers.
  - Secret recovery (`handleSecretRecovery`): records superseded tombstones for unaccepted pending action IDs.
  - Native WebSocket support: hibernation attachment handling with in-memory fallback for test environments, initial snapshot message, event broadcast.
- `worker/api/matches.ts`: Worker match routes:
  - `POST /api/v1/matches`: Creation idempotency by `creationId`, slot reservation in `active_slots` (`shared:<game>:remote` / `shared:<game>:together`), DO initialization, participant resolution.
  - `GET /api/v1/matches`: Query match registry for caller-accessible matches.
  - `GET /api/v1/matches/:id`: Snapshot view from DO.
  - `POST /api/v1/matches/:id/actions`: Action envelope delivery to DO with accepted/rejected replies.
  - `GET /api/v1/matches/:id/receipts/:actionId`: Receipt status without disclosing digests or private choices.
  - `POST /api/v1/matches/:id/controller`: Intentional controller takeover.
  - `POST /api/v1/matches/:id/secret-recovery`: Atomic secret recovery.
  - `GET /api/v1/matches/:id/socket`: WebSocket upgrade to DO.
- `worker/index.ts`: Mounted `/api/v1/matches` router and exported `MatchDurableObject`.
- `tests/integration/matches/do-mock.ts`: In-memory DO storage and DO namespace mock backed by `node:sqlite` `DatabaseSync` for integration testing.
- `tests/integration/matches/matches.test.ts`: Integration test suite covering:
  - Match creation and unique slot reservation (`shared:connect-four:remote`, `shared:connect-four:together`).
  - Idempotent action delivery returning cached reply with identical version, event ID, and timestamp.
  - Rejection of action ID reuse with different payload (`ID_REUSED`).
  - Rejection of out-of-turn moves (`NOT_YOUR_TURN`).
  - Full Connect Four gameplay with disc drops, gravity simulation, vertical win detection, terminal result, and slot cleanup.
  - Controller takeover incrementing generation and rejecting stale controller generation (`CONTROL_TRANSFERRED`).
  - Snapshot fetch, receipt inspection, and secret recovery tombstones (`ACTION_SUPERSEDED`).

## Findings and Limits
- In `match-do.ts`, SQLite queries inside `transactionSync` are synchronous, adhering to Cloudflare's storage API constraints. Durable synchronization is awaited immediately following the transaction before replying or broadcasting.
- D1 projection outbox is decoupled from the synchronous move commitment: if D1 lags or fails, the move has already been accepted and saved durably in DO SQLite; the DO will retry projection with exponential backoff on subsequent match actions or alarms.
