## Implemented Behavior & Rules (HC01–HC05)

### 1. Toss and Role Selection (HC01)
- Initial state initialized with `phase: "toss"`, `innings: 1`, `deliveryId: 1`, and `tossWinner` derived deterministically from `startFacts.startingSeat`.
- Only the `tossWinner` can execute `cricket.choose-role` with `payload: { role: 'bat' | 'bowl' }`.
- Other seat calling `cricket.choose-role` is rejected with `ErrorCode.NOT_YOUR_TURN`.
- Invalid role payloads rejected with `ErrorCode.INVALID_ACTION`.
- Role assignment:
  - Choosing `'bat'`: `tossWinner` is `bat`, opponent is `bowl`.
  - Choosing `'bowl'`: `tossWinner` is `bowl`, opponent is `bat`.
- State transitions to `phase: "first_innings"`.
- Emits effects: `toss-resolved` and `role-chosen`.

### 2. First Innings Delivery Lifecycle and Run Scoring (HC02)
- In `phase: "first_innings"`, both seats secretly lock numbers 1..6 via `secret.lock` (`payload: { value: 1..6 }`).
- Numbers outside 1..6, non-integers, or invalid types rejected with `ErrorCode.INVALID_ACTION`.
- Duplicate locks by the same seat in the same delivery rejected with `ErrorCode.CHOICE_LOCKED`.
- While one player has locked, their number is stored in `secretDeliveries` and their seat recorded in `lockedSeats`.
- When both seats have locked:
  - Batter number and bowler number are compared.
  - If different numbers: batter scores their played number (`firstInningsRuns += batterNumber`), outcome is `"runs"`. Emits `delivery-resolved`.
  - Both players acknowledge delivery with `secret.next`. Premature delivery locking before acknowledgment is rejected.
  - Upon both calling `secret.next`, `deliveryId` advances by 1, clearing `secretDeliveries` and `lockedSeats` for the next ball.

### 3. First Innings Dismissal & Target Setting (HC03)
- If batter number and bowler number are equal: batter is OUT (`outcome: "out"`). Emits `wicket-fallen`.
- Target is set: `target = firstInningsRuns + 1`.
  - Special case: 0 runs in 1st innings results in `target: 1`.
- Innings swap occurs when both players confirm `secret.next`:
  - Roles swap (`bat` becomes `bowl`, `bowl` becomes `bat`).
  - Sets `innings: 2`, `deliveryId: 1`, and `phase: "second_innings"`.
  - Emits `innings-swapped` with `newBatter`, `newBowler`, and `target`.

### 4. Second Innings Chase & Terminal Conditions (HC04, HC05)
- In `phase: "second_innings"`, both seats secretly lock numbers 1..6.
- Run Scoring & Immediate Target Reached (HC04):
  - If numbers differ, chasing batter scores their played number.
  - If `secondInningsRuns >= target`: chasing batter wins immediately!
  - `phase` becomes `"terminal"`, `terminalResult` created with `reason: "rules_win"`, winner set to chasing batter seat. Emits `game-won`.
- Dismissal & Defended Total / Draw (HC05):
  - If numbers match: chasing batter is OUT. Match concludes immediately in `phase: "terminal"`.
  - If `secondInningsRuns === firstInningsRuns`: match is a DRAW (`reason: "rules_draw"`, `winner: null`). Emits `game-drawn`.
  - If `secondInningsRuns < firstInningsRuns`: first batting team (now bowling) defended their total and wins (`reason: "rules_win"`). Emits `game-won`.

### 5. Privacy, Immutability & Adapter Contract
- **Privacy**: `toPublicView` strips `secretDeliveries` completely. Secret delivery numbers are NEVER exposed to the public view while a delivery is unresolved. Only `lockedSeats` is visible. Once resolved, `lastDelivery` exposes the resolved ball outcome.
- **Immutability & Determinism**: Reducers are pure functions with no clocks, random generators, or I/O. Actions leave state unchanged on error. Survives JSON serialization and round-trip.
- **Adapter**: `handCricketEngineAdapter` implements `GameEngineAdapter<CricketState, CricketActionPayload, CricketEffect, CricketView>` with `gameId: "hand-cricket"`.
