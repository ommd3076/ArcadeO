## Implemented

- **A06-T1:** Login failures now use one SQLite/D1 UPSERT per normalized account key and IP key. The window rollover, increment, and threshold/block calculation occur in the SQL statement, so overlapping failed logins do not overwrite one another with a stale read. Successful login still resets only that account counter; attempts remain bounded by the existing 15-minute window and limits.
- **A06-T2:** Production API routing requires a configured, exact HTTPS `ALLOWED_ORIGIN`; wildcard, missing/inferred, HTTP, path, and other non-origin values fail closed with a no-store JSON configuration error. Direct auth origin checks also reject production wildcards. Production login emits the Secure, HttpOnly, SameSite=Lax, Path=/ `__Host-arcade-session` cookie without Domain. Local development retains its explicit LAN origin and HTTP development cookie behavior.
- **A06-T3:** API exceptions return safe no-store JSON `503 UNAVAILABLE`; unknown API paths return JSON `404 NOT_FOUND`; authored app document routes use the public shell; unknown document paths render the authored router fallback with HTTP 404. Missing assets pass through the asset binding and retain its actual 404 rather than SPA HTML. The initial `/index.html` asset-binding redirect recursed under worker-first routing, so the shell fetch now asks the binding for `/` directly.
- **A06-T4:** Regressions confirm repeat provisioning preserves both existing accounts’ password verifiers, display names, and account preferences; exactly two fixed accounts remain. The provisioning script accepts account passwords through `ACCOUNT_A_PASSWORD`/`ACCOUNT_B_PASSWORD` (or `PLAYER_A_PASSWORD`/`PLAYER_B_PASSWORD`) and writes generated SQL under `.local`; it prints usernames but not passwords. For production, use the prepared Arcade-specific config, exact origin, and interactive `npx wrangler secret put CSRF_SECRET --config .local/wrangler.arcade-production.json`; never put credentials in Wrangler vars, generated tracked SQL, or reports. This verifies code/config behavior only, not production provisioning.
- **A06-T5:** Client API requests now use one 12-second default deadline over response headers and body, honor caller cancellation, cap buffered response bodies at 4 MiB, and retain normal `Response` status/header/body methods for current consumers. Timeout, cancellation, and network failures become actionable messages; HTTP 401/403/404/409/429/503 and malformed JSON remain response-level results for existing callers. Auth bootstrap has a themed loading/error surface, a 52px retry control, a working reduced-motion state, and exits “Opening your arcade…” when its bound expires. Reader cancellation is cleanup-only: both synchronous throws and rejected cancellation promises are consumed, including when the response stream already errored. A monotonic auth-session epoch plus refresh sequence prevents old bootstrap/session responses and old 401s from overwriting or clearing newer auth state. A successful logout clears the session-bound CSRF identity it revoked even if a same-session refresh committed during the request; publishing null advances the epoch so older refreshes cannot restore it, while a different token preserves a genuinely newer login.

## Logout/refresh race follow-up

The successful logout and protected API 401 responses now clear a session identity revoked by the server even if a same-session preference refresh commits while the response is pending. `csrfToken` is session-bound: `worker/auth/session.ts` derives it as an HMAC over the raw session token with the `arcade-csrf-v1` purpose tag. The client captures that identity when each request starts and clears only a matching current session after a server-confirmed 401/logout. A different current CSRF token is left signed in as a genuinely newer login, while unauthenticated bootstrap requests retain the epoch guard. Unit regressions cover both 401 interleavings, the logout refresh race, newer login preservation, and pending refresh invalidation. `tests/browser/overnight-auth-race.spec.ts` retains the late unauthenticated bootstrap regression and adds the real-provider logout race: the test holds logout, performs preference save, holds and releases the session response, waits for the refresh request to finish, then releases the actual Worker logout response (HTTP 200). It confirms the app reaches `/login` without the Primary private navigation. `npx playwright test tests/browser/overnight-auth-race.spec.ts` passed **2/2** against the integrated built local Worker before this 401-only follow-up. Focused auth/provisioning tests now pass **16/16**; typecheck, scoped ESLint, Prettier, and `git diff --check` pass. No browser or build was run for the 401-only follow-up.
