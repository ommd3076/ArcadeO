## Owned Paths and Files Changed
- `src/sync/types.ts`: Complete TypeScript types and interfaces:
  - Connection lifecycle states: `"connected" | "connecting" | "disconnected" | "reconnecting"`.
  - Sync states: `"idle" | "syncing" | "reconciling"`.
  - Pending action states: `"in-flight" | "retrying" | "reconciling"`.
  - `PendingAction`: In-flight action tracking (`actionId`, `action`, `payload`, `expectedVersion`, `roundId`, `turnId`, `controllerGeneration`, `isSecret`, `status`, `submittedAt`, `retryCount`).
  - `PendingActionMetadata`: Scoped session storage interface strictly omitting secret values.
  - `ControllerStatus`: Controller authority tracking, current generation, and takeover alert flag.
  - `SessionError`: Typed session error payload (`code`, `message`, `retryable`, `timestamp`).
  - `MatchSessionState`: Authoritative reducer state holding latest view, delivery version, pending command, connection/auth/controller status, offline pause, and secret masking indicator.
  - `SocketServerMessage`: Discriminated union of snapshot, contiguous events, controller changes, heartbeat pings/pongs, and action responses.
  - `MatchSessionOptions`: Configurable transport, endpoints, backoff parameters, custom fetch, and storage injectors.
- `src/sync/match-session.ts`: State machine and client synchronization manager:
  - Delivery version sequencing: accepts higher-version snapshots, applies contiguous updates (`acceptedVersion === deliveryVersion + 1`), drops duplicate/stale updates (`acceptedVersion <= deliveryVersion`), and immediately recovers snapshot when a gap is detected (`acceptedVersion > deliveryVersion + 1`).
  - Single pending command tracking: strictly enforces at most one action in flight; concurrent submissions reject immediately.
  - Native WebSocket transport with heartbeat ping/pong (15s interval) and exponential backoff reconnection.
  - HTTP polling fallback: automatically activates when WebSocket is unavailable or repeatedly fails; active only when document is visible (`!document.hidden`) and suspends during background tabs.
  - Offline input pause: immediately pauses user inputs (`isInputPaused === true`) when disconnected, reconnecting, or offline; never queues offline edits.
  - Reconnection reconciliation: conceals unrevealed secrets (`secretChoiceMasked = true`) first, fetches latest view on reconnect/pageshow/focus/online, drops stale actions, and preserves nonsecret action IDs for idempotent retry.
  - Secret lock recovery: calls `POST /api/v1/matches/:id/secret-recovery` if an uncertain secret lock was in flight; supersedes unaccepted attempts without ever writing secret choices to client storage.
  - Controller takeover: captures `control-changed` socket messages, sets `takeoverNotice`, and allows dismissal.
- `src/sync/use-match-session.ts`: React hook for screen consumption:
  - Subscribes to `MatchSession` state machine with cleanup on unmount.
  - Binds `sendAction`, `retryPendingAction`, `reconcile`, `unmaskSecretChoice`, `dismissTakeoverNotice`, and `clearError`.
- `src/sync/index.ts`: Barrel export file for the sync subsystem.
- `src/components/connection-status.tsx`: Prominent, accessible status banner reflecting:
  - `"Connecting..."` and `"Reconnecting..."` with animated indicator.
  - `"Disconnected — inputs paused"` and `"Offline — inputs paused"` with retry/connect trigger.
  - `"Syncing..."` during snapshot catchup or reconciliation.
  - Controller takeover notifications (`"Control transferred to this device."` / `"Control transferred to another device — inputs paused."`) with dismiss action.
  - Accessible semantics: `role="status"` / `role="alert"`, `aria-live="polite"` / `aria-live="assertive"`.
- `tests/unit/sync/sync.test.ts`: Comprehensive unit test suite covering:
  1. Delivery version sequencing, stale snapshot rejection, contiguous event application, and gap detection with snapshot recovery.
  2. Single pending command tracking, concurrent action rejection, server rejection propagation, and idempotent retry preserving exact `actionId` and `payload`.
  3. Offline pause state transitions and rejection of offline action submissions.
  4. Secret choice storage redaction (choices never stored in `sessionStorage`), immediate masking on reconnect/focus, and atomic secret recovery.
  5. HTTP polling fallback and document visibility suspension.
  6. Controller takeover alerts and notice dismissal.

## Findings and Limits
- In accordance with the project contract, raw secret choices (e.g. RPS choices or Hand Cricket values) are strictly ephemeral in memory and never written to `sessionStorage` or logs. Upon reconnect or page visibility restoration, secret inputs are masked before fetching authoritative server state.
- Single in-flight command serialization guarantees deterministic client-side synchronization without out-of-order race conditions.
