## Confirmed defects and resulting behavior

1. **Critical: asynchronous action races.** The original handler loaded its snapshot before awaiting the payload digest, allowing simultaneous handlers to consume the same saved version. Initialization, action acceptance, recovery tombstones and takeover now share one authority queue. Guard/reduction/transaction have no asynchronous yield. Identical retries return the original event/version with the latest filtered view; changed payload IDs reject. Related snapshot/event/receipt/private-choice/outbox writes commit in one synchronous SQLite transaction, followed by durable synchronization before acceptance or broadcast.
2. **Critical: control and authorization bypass.** Together generation was optional and only lower generations rejected; account-only control allowed an old session to continue. Exact generation and persisted controller session are required. Sudoku has per-account controllers with its own revision rather than opponent/global delivery version. Takeover requires the expected generation and cannot modify terminal lifecycle. Every new socket/HTTP authority write and socket delivery checks an unexpired, unrevoked session through D1 primary reads. Missing auth storage fails closed. Nonmember reads and receipts do not disclose a view. Removed implicit account A fallback.
3. **Critical: secret disclosure and recovery race.** Raw effects were returned in receipts and broadcast, including masked together resolutions; Sudoku effects exposed private edited/check cells. Delivery filters all these paths. Together secret effects stay hidden until saved Reveal; Sudoku effects are withheld and own view supplies accepted changes. Receipt digests/raw choices remain private. Atomic recovery returns an existing safe accepted receipt or saves a lifetime superseded tombstone before permitting another choice. Old lock IDs cannot land after recovery.
4. **High: socket lifecycle.** Replaced ordinary in-memory listeners with native hibernation callbacks and attachments. Restored sockets are enumerated from DurableObjectState.getWebSockets; identity/session metadata lives in attachments, never rules/choices. Upgrade requires exact configured Origin, membership and current session. Malformed socket failures use a fixed safe message rather than interpolating exception text.
5. **High: incorrect authority turn/round/randomness.** The DO used to alternate the seat for every reduction and never advance its secret round. It now derives activeSeat from the accepted engine state, preserving bonus/scoring turns and uses saved roundId/monotonic cricket deliveryId. Dice and creation toss use cryptographic rejection-sampled facts. Lifecycle version, turn/version, round and own Sudoku revision guards are mandatory in their applicable paths. Unsupported protocol/schema/rules reject without reset.
6. **High: invitation/terminal behavior.** Accept and both Ready are distinct remote actions. Creator/invitee cancellation roles and inactive gameplay are checked. Abandon requests and the other seat's agreement are saved in authority metadata. A winning together secret outcome cannot be overwritten by resignation/abandonment before its presentation Reveal. Terminal results remain immutable. Together named resignation requires strict A/B.
7. **High: creation and reservations.** Original creationId replay ignored actor/payload, did not repair partial initialization and relied on stale D1 lifecycle to release slots. Canonical original creation payload is saved, conflicts reject, existing saved authorities resume, failed initialization can be retried with the same ID. Unique D1 batch reservation resolves simultaneous creations. Slot reconciliation checks the DO. An uninitialized reservation older than ten minutes is atomically tombstoned in the DO before conditional slot release, so a delayed initialize cannot create an orphan. Initialized data is retained. Async sender and published challenge slots are separate.
8. **High: projection reliability.** Result replacement was unconditional and no retry alarm existed. Result upsert is version conditional; registry projection remains version conditional. Failed outbox writes get capped backoff and a durable alarm, also retried on later activity. Background work is held with waitUntil. Controller changes also persist projection work. Completed Sudoku records are safe per-player metadata saved with accepted outbox state; no solution/board is projected. Outbox success deletion and failure updates include the loaded requiredVersion, so replacing a queued revision during an asynchronous projection cannot discard newer work. A slow-projection/new-acceptance regression covers that interleaving. Root also made Sudoku assisted/replay projection monotonic.
9. **High: Sudoku issuance/start.** Generic creation could trust caller solution/default zero grids and did not start duel clocks correctly. Catalog givens and private server solutions replace caller data, invalid IDs reject, duel eligibility uses both accounts' completed puzzle history. Both Ready fixes one shared start three seconds ahead. Published challenge acceptance fixes receiver start and rechecks receiver completion for replay eligibility. Internal challenge-source export reads an eligible saved sender attempt and returns duration/puzzle metadata only.
